# Agent Skills 型を評価の基準線にする

## 目的

提案 01 の条件 (B) として、より単純な代替案を薄く実装し、SkillSmith の合成段と公平に比べられるようにします。

## 現状の問題

事実: 現在は比較対象がなく、SkillSmith が単純な「メタデータ → 本文」の段階的開示より優れているかを判断できません。

## 提案

候補 Skill のメタデータ（名前・説明）をまず実行側へ渡し、実行側モデルが必要と判断したものだけ本文を読む経路を、評価専用に用意します。適用するかどうかは実行側モデルが判断し、合成段は通しません。Anthropic の製品は複製せず、公開記事の考え方だけを参考にします。

## 検証（採用 / 不採用）

採用判定は、提案 01 の固定タスク集合（未整備なら提案 14 の評価キット）で変更前後を同じ record から比較し、下の条件で決めます。悪化した場合は変更を戻し、不採用の理由を本ファイルに追記します。 基準線そのものの採否は、提案 01 の比較に耐える再現性（同じ record で同じ結果）があるかで決めます。

## よくなったとみなす条件

基準線が同じ検索結果を使い、差が合成段の有無だけに絞れていることです。

## 悪化したとみなす条件

基準線が検索段まで別物になり、比較が交絡することです。

## やらないこと

基準線を製品機能として公開しません。基準線を意図的に弱く作りません。 本番の ContextStill への接続、語句辞書やキーワードによる意味分岐、費用上限によるゲートは行いません。推論は Grok Bot が recorded-inference の継ぎ目を通して行います。

## 依拠（コード・論文）

コード: `src/service/build.ts` の検索結果の取りまとめ。論文: Agent Skills（上記 URL）、Lost in the Middle https://arxiv.org/abs/2307.03172 。

## 依存・前提

前提: 提案 01、14。



## 実装結果

- **採否**: 採用（評価専用基準線）
- **内容**: 同じ cards/evidence を受け、disclose → apply/skip だけの薄い基準線。合成段なし。section なし資料は全文フォールバック。
- **パス**: `src/eval/baseline.ts`, `src/eval/disclosure.ts`（05 と共有）, `src/test/eval-baseline.test.ts`
- **試験**: `bun test src/test/eval-baseline.test.ts`
- **verify**: 後続コミット群の末尾で一括確認
- **理由**: 検索結果を呼び出し側から渡すため、差は合成段の有無に絞れる。製品の build 経路は置き換えない。
