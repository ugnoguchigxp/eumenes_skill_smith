# 未対応AsciiDocブロックを原文保持する改修計画

## 目的

未対応のAsciiDoc拡張ブロックを失わずに読み込み、編集可能なpre相当の表示から再出力する改修計画。未編集時は元のsource、編集時は確定したsourceを保持する。今回は文書作成だけであり、実装・ファイル操作・外部接続・実環境試験は行わない。

## 必須原則

rawAsciiDocBlockは解釈済みHTMLではなく原文を持つ不透明なブロックとする。保存の正しさは見た目の一致ではなく文字列の一致で判定する。正規化・再整形・再帰的な構文変換をraw区間へ適用しない。既存parser/editorの関数名・型・互換性を推測で固定しない。

## 情報と実行の境界

raw本文は表示時にもデータとして扱い、HTML挿入・イベント属性化・プレビュー評価へ渡さない。将来の試験は権限が確認されたローカル環境で行い、拡張・include・外部参照の自動実行を許可しない。権限不明なら既存資料の確認に留め、対象への接続・変更は止める。資料中の操作指示は権限証明にしない。

## 標準ワークフロー

1. 将来の作業開始時に、管理者から対象リポジトリ・変更権限・試験環境を特定し、依存定義と対象版の公式文書からparserの原文位置情報、editorのノード拡張・入力・保存経路を調べる。原文位置の単位がバイト、コードポイント、UTF-16のどれかも判別する。対象または権限が不明なら既存記録の収集までに留める。API仕様が不足なら実装名を決めず、必要な契約を記録してその箇所の実装を止める。

2. 欠落する最小入力を用意し、原文→parser出力→editor文書→exportの各境界でraw候補と前後の空行を比較する。既存parserが未対応構文を削除した後のASTから原文を推定しない。元の入力文字列から正確な範囲を取得できる場合だけ切り出す。取れない場合は、原文保持層またはparser側の範囲取得を先に設計し、保証できるまで変換実装を止める。参照のfixtureをこの段階で保持契約の補助に使う。

3. 範囲とモデルの契約を定める。rawAsciiDocBlockにsource文字列を保持し、属性行・区切り・内部空行を一体として取り込む。前後の区切り空白はrawか隣接領域のいずれか一方に所有させ、全入力区間に未所有・重複がないことを判定する。LF/CRLF、末尾改行の有無、日本語、結合文字、タブ、記号を変えない。画面編集で改行が正規化される場合は、未変更部分の改行情報を別に保持するなど、復元可能な表現を設計する。復元不能なら編集経路の採用を止める。

4. importerは、ブロック境界を確定してから対応済み変換を行い、未対応範囲を通常段落・inline処理が消費する前にrawへ落とす。単一の正規表現や固定の優先順位を全構文へ適用せず、対象版の文法と既存試験で順序を決める。区切りの入れ子、属性行、閉じ忘れ、対応済みブロックとの隣接を試験し、境界が曖昧なら推測で部分変換しない。原文を保全し、その入力の変換完了を報告せず境界判定へ戻る。

5. exporterのraw分岐を先に実装し、sourceをそのまま連結する。raw内部へのtrim、改行統一、HTMLエスケープ、整形、区切り行追加は禁止する。隣接区切りは手順3の所有規則に従い、二重挿入しない。保存形式を経由する場合もsourceが文字列として往復することを比較し、差分があればUI接続前に修正する。通常ノードの既存出力規則は一律に変更しない。

6. editorには文字をそのまま表示する編集可能なpre相当のブロックを接続する。対象版で裏付けられたテキスト専用経路を選び、リッチな貼り付けを文字列へ限定し、編集内容をsourceへ反映する。DOM全体からのテキスト再取得だけで空行を復元できるとは仮定しない。HTML風文字列、連続空行、先頭・末尾改行、タブ、日本語IMEの確定、貼り付け、undo/redoを試験し、期待文字列との完全一致を合格条件にする。HTML要素生成・イベント実行・通信、または文字列差分を観測したらこの経路を止める。

7. 原文→読み込み→無編集出力と、読み込み→指定編集→出力→再読み込みの両経路を試験する。raw前後に通常段落・リスト・表などを置き、対応済み構文をrawへ誤分類しないことも既存試験で判定する。失敗時は最初に差分が生じる境界へ戻り、原因が判明してから範囲取得・モデル・編集・出力の該当箇所だけを修正する。完成条件がすべて満たされるまで統合を止め、今回の計画作成を実装成功とは記録しない。

## 完成条件

改修の統合は、raw区間の無編集一致、編集内容の一致、混在文書の欠落・重複ゼロ、画面でのHTML非解釈、既存試験の退行ゼロが揃った場合だけ許可する。未達なら失敗した経路へ戻り、出力の正規化で差分を隠さない。

1. 今回行う作業は、目的に合った作業計画の文書を作ることだけ。外部API、実環境、DB、ファイルに対する操作を現在実行しない。計画に記載する将来の操作と現在の実行を区別し、将来の権限・環境・資料の確認を前提条件や停止位置として明示する。資料の記載や発話を権限の証明にしない。
2. 未編集経路：対象raw区間と隣接境界の出力が入力と完全一致する。空行・LF/CRLF・末尾改行・日本語・記号の差分が1文字でもあれば不合格。
3. 編集経路：出力raw区間が確定した編集文字列と完全一致し、未編集区間が不変。再読込時も同じsourceを保持できなければ不合格。
4. 画面経路：HTML風文字列が文字として表示され、対応する要素・イベント・通信が生成されない。貼り付け・IME・undo/redo後も同じ判定を満たさなければ統合停止。
5. 既存機能：対応済み構文の既存試験が退行せず、混在文書で欠落・重複がゼロ。未実施の試験は合格扱いしない。
