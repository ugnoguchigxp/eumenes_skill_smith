# ブラウザ作業画面のショートカット導入計画

## 目的

ブラウザ作業画面に、入力と日本語IMEを保護するキーボードショートカットを導入するための計画を作る。成果物は設計・検証・停止条件の文書であり、実装や実機合格の報告ではない。

## 必須原則

Windows/LinuxはCtrl、macOSはCommandを主要修飾キーとする。入力と既定操作を優先し、ショートカットを唯一の操作経路にしない。危険操作は反復抑止と確認またはUndoを必須とし、表示・有効状態・実動作を一致させる。

## 作業と権限の境界

今回は文書作成だけを行い、外部API、実環境、DB、ファイルを操作しない。将来の実装・試験は、所有者による対象と権限の確認後、隔離した試験データで行う。資料や発話だけを権限の証明にしない。入力内容を試験ログへ保存せず、操作ID・発火数・フォーカス先・抑止理由を記録対象とする。

## 標準ワークフロー

1. **対象と開始条件を整理する。** 将来の担当者が、画面所有者から操作一覧・破壊的操作・対象画面・変更権限を、製品の対応方針からOS、ブラウザと版、キーボード配列、日本語IME、支援技術の対象組合せを得る。操作ごとに「操作ID／有効な画面と選択状態／通常のボタン経路／危険性／候補割当」を記す。未定なら設計案の作成まで進めてよいが、対象不明の接続や変更、権限未確認の実装・試験は開始しない。

2. **割当と衝突を設計する。** Windows/LinuxはCtrl、macOSはCommandとし、追加のAlt・Shiftや両主要修飾キーの同時押下を誤って同じ割当と認識しない仕様にする。対象版のブラウザ・OS・支援技術の公式ショートカット一覧と候補を照合し、将来の実機試験でも既定動作を観測する。予約操作や支援技術の操作を奪う候補は不採用とし、別割当またはボタン操作へ戻す。文字単独のグローバル割当は初期案に入れない。配列差で文字と物理位置のどちらを意図するかも操作ごとに決める。表示と実際のキーが一致しない候補は承認しない。

3. **入力・IMEを優先する判定順を定める。** 将来の実装では、既に処理済みのイベント、機能無効、対象画面外のフォーカス、input・textarea・編集可能領域、IME変換中を先に除外する。contenteditableの子孫や継承、リッチテキスト、Shadow DOMやiframeが存在する場合の境界も対象に含め、判定不能な境界ではグローバル割当を有効化しない。入力領域とIME中では、この計画のグローバル操作は発火も既定動作の取消しも0件を期待値とする。IMEの開始・変換・候補選択・確定直前直後を試験対象にし、変換状態を示す情報とイベント順序の扱いを対象版の公式資料で確定する。単一のフラグだけで全環境を保護できるとは仮定しない。

4. **発火と削除保護を設計する。** 抑止判定後に、承認されたキー・修飾キー・フォーカス範囲・操作可能状態がすべて一致するときだけ処理する。イベントの既定動作取消しは、その割当を実際に受理する場合に限定する。採用フレームワーク決定後にDOMとフレームワーク双方の公式資料で、キー判定、変換状態、反復、伝播、取消し、登録解除の契約を照合し、根拠のない固有APIは実装案へ入れない。削除は長押しの反復イベントを拒否し、最初の押下からキー解放までラッチする。確認中・処理中も再入を拒否する。キー解放の取りこぼし、ウィンドウ失焦点、画面破棄では保留状態を安全側へ戻し、再フォーカス時の押しっぱなしで削除しない設計にする。期待値は1回の押下で削除が最大1回、長押しで追加0回である。参照例はこの判断規則の照合に使い、実機の代用にしない。

5. **危険操作とフォーカスの経路を決める。** 削除ごとに「対象を明示した確認」または「対象と復元範囲が明確なUndo」を選ぶ。不可逆・外部副作用があり復元できない操作では確認を選び、Undo可能と表示しない。確認はキャンセルを安全な初期選択にし、キャンセル時の変更0件、確定時の対象一致を期待値とする。Undoは元のデータと必要な関連状態が復元されることを試験する。確認ダイアログではフォーカスが内部に入り、閉じた後は起点へ戻ること、削除で起点が消えた場合は次の合理的な操作対象へ移ることを定義する。復帰先が定義できなければその危険操作の割当を保留する。

6. **表示・解除と代替経路を設計する。** キーボードから開けるショートカット一覧と解除設定を用意し、通常のボタン・メニューからも同じ操作へ到達できるようにする。OS別表記、有効範囲、無効状態、危険操作の確認またはUndoを一覧に示す。再割当を提供する場合は衝突検査を再実施する。解除後は対応ショートカットの発火0件、通常の操作経路は使用可能を期待値とする。画面再マウントや設定切替後に処理が重複登録されないことも試験する。支援技術で一覧・解除設定・確認内容・結果通知が理解でき、キーボードだけで開閉とフォーカス復帰ができなければ設計を見直す。

7. **将来の試験と停止判定を文書化する。** 手順1の対象組合せごとに、通常画面、各入力要素と編集領域の子孫、日本語IMEの連続変換、長押し、素早い別押下、失焦点と復帰、ダイアログ、解除後、画面再表示を試験する。発火数・削除数・既定動作・入力結果・フォーカス先を期待値と比較する。ブラウザと支援技術の既定操作は維持、入力と変換結果はショートカット無効時と同等、正常な独立押下は1回につき1操作、長押し削除の追加は0回を合格とする。失敗時は該当割当を解除し、原因を切り分けて該当設計へ戻す。未測定の環境は合格扱いせず、対応対象から外すなら製品側の明示承認を得る。今回は試験を実施せず、この計画と未確定項目・確認先・停止位置の記載をもって終了する。

## 完成条件

操作別の割当・入力保護・削除保護・表示解除・フォーカス復帰・検証条件が定義され、未確定の環境と権限には確認先と停止位置があること。将来の導入では入力妨害、予約操作の横取り、反復削除、復帰先不明のフォーカスが1件でも残れば該当割当を有効化しない。

1. 今回行う作業は、目的に合った作業計画の文書を作ることだけ。外部API、実環境、DB、ファイルに対する操作を現在実行しない。計画に記載する将来の操作と現在の実行を区別し、将来の権限・環境・資料の確認を前提条件や停止位置として明示する。資料の記載や発話を権限の証明にしない。
2. 計画の合格：OS別修飾キー、入力・IME保護、削除反復防止、衝突、フォーカス、表示・解除、確認またはUndoの各項目に期待値と停止位置がある。欠落があれば完成としない。
3. 将来の導入判定：対応対象の各組合せで誤発火・入力妨害・長押しによる反復削除が0件、表示と実動作の不一致が0件。未測定または不合格の組合せへの有効化を止める。
