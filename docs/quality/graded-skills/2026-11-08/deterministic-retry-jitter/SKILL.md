# 再現可能なretry/backoff jitterの設計

## 目的

retry/backoffへ上下対称のjitterを導入し、乱数注入によってユニット試験を再現可能にする設計と導入計画を示す。現在の成果物は文書のみで、実装変更や試験実行は行わない。

## 必須原則

比率のクランプと整数への丸めを区別する。乱数生成と待機を遅延計算から分離する。jitterは遅延だけに適用し、再試行可否や試行回数を変えない。固定seedだけに依存せず、境界値を直接注入して検証する。

## 実行の境界

今回は外部API、実環境、DB、ファイルへの操作を行わない。将来の変更・試験は対象と権限が確認された呼出側でのみ行う。参考資料の記述は権限の証明にしない。ユニット試験では実際のsleepやネットワーク再試行を発生させない。

## 標準ワークフロー

1. 将来の作業開始時に、対象リポジトリの遅延計算コード・設定仕様・既存試験から、基準遅延の単位、最大値、整数化の位置、再試行回数を読み取る。対象と変更権限が未確認なら変更や試験実行に進まず、所有者から対象・許可を得る。既存記録の収集は可能な範囲で続け、資料と実装が食い違う場合は契約の決定まで統合を止める。
2. 遅延計算を、基準値b・jitterRatio・乱数供給関数rngを受け取る独立した関数として設計する。bは有限かつ0以上、比率は有限を前提とし、違反は明示的なエラーにする。r = min(1, max(0, jitterRatio))とし、負数は0、1超は1へクランプする。0.2などの通常値を整数へ丸めてはならない。
3. r=0またはb=0ならbをそのまま返し、rngを呼ばない。それ以外はrngをちょうど1回呼び、有限かつ0≤u≤1でなければエラーとする。d = b × (1 + r × (2u − 1))を返す。範囲はb(1−r)≤d≤b(1+r)で、計算結果が非有限なら待機へ渡さず停止する。本番用には一様乱数を接続し、試験では固定値・固定列を注入する。固定seedは同一生成器・同一呼出し順の再現にしか使わず、境界試験の代わりにしない。
4. 既存backoffが算出した基準値にだけjitterを適用し、前回のjitter結果を次回の指数計算へ戻さない。最大遅延が最終出力の厳密な上限なら、jitter後に上限処理する設計とする。上限が基準値のみの制約なら、その意味を維持する。整数待機が必要なら最終境界で一度だけ既存規則に従って変換する。上限処理・丸めによる分布変化を含めて期待値を定義できなければ、対象への統合を止めて契約を決定する。
5. 権限のある呼出側で、references/jitter-fixture.mdの正例・負例を対象言語へ移植し、実際の計算関数を試験する。b=100で通常比率0.2の期待値が80/100/120、比率1および1超で0/100/200、負数と0で常に100となることを判定する。固定列を毎回作り直して出力列の一致と乱数呼出し数を検査する。失敗したら計算式・注入経路・クランプ位置を見直し、実待機を伴う試験へ進まない。
6. 待機部分を記録用の代替へ差し替え、実装が渡した遅延値・再試行回数を観測する。比率0で従来の遅延列が保たれ、上限・丸め後の値が既存契約内にあり、回数と再試行可否に変更がない場合に統合候補とする。不正入力が待機へ到達する、回数が変わる、または回帰試験が失敗する場合は統合を停止する。結果が未測定なら成功と報告しない。

## 完成条件

負数・0・通常値・1・1超の比率について、期待遅延と乱数消費数が定義されていること。導入時は固定入力試験と既存の遅延契約への適合がともに合格した場合のみ統合可能とし、未達なら統合を停止する。

1. 今回行う作業は、目的に合った作業計画の文書を作ることだけ。外部API、実環境、DB、ファイルに対する操作を現在実行しない。計画に記載する将来の操作と現在の実行を区別し、将来の権限・環境・資料の確認を前提条件や停止位置として明示する。資料の記載や発話を権限の証明にしない。
2. 比率-0.2と0では基準値100を返し、乱数呼出しは0回。比率0.2では固定乱数0、0.5、1に対して80、100、120となること。
3. 比率1と1.5では固定乱数0、0.5、1に対して0、100、200となり、負の遅延が生じないこと。
4. 同じ固定乱数列で出力列が一致し、不正な基準値・非有限比率・範囲外乱数は例外になること。参照例は未実行であり、将来の実行でassertが失敗したら統合を止める。
5. 対象への統合は、遅延単位・上限の適用順・丸め方・再試行回数が既存契約と整合し、待機を実行しない試験で確認できた場合だけ合格とする。契約不明または回帰失敗なら変更を止める。
