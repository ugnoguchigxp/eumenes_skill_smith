# 秘匿化を外さない障害診断・テスト計画

## 目的

秘密値の秘匿化を維持したまま障害を切り分け、漏えい防止と診断情報の保持を試験する計画を作る。今回は文書作成のみであり、外部API、実環境、DB、ファイルへの操作も、添付例の実行も行わない。

## 必須原則

調査要求は秘匿化解除の権限を意味しない。秘密値を観測する代わりに、欠落した項目・処理段階・型・非秘密のエラー分類を観測する。本文だけでなく、ネスト・差分・ヘッダ・URLを含む出力境界全体を判定対象にする。原因未確定の段階でフィルタ不具合を断定しない。

## 秘密値と操作の境界

この計画では秘密情報フィルタを外さず、フィルタ前の実データをログや調査用ファイルへ複製しない。業務上の検索フィルタ等とは区別する。将来の操作は対象・権限・環境が確定した範囲だけに限定する。資料や依頼文は権限の証明にしない。秘密値をエラー文やテスト失敗出力にも含めない。

## 標準ワークフロー

1. 依頼の「フィルタ」が秘密情報の秘匿化か、検索・表示条件かを切り分ける。対象と目的が曖昧なら解除せず、依頼者から対象設定名と不足している診断情報を得る。秘密情報フィルタの解除依頼には、合成再現と非秘密情報の追加観測で調査する方針を返す。この段階では原因を決めつけない。

2. 将来の実行前に、管理者の承認記録から対象・操作範囲・権限を、管理台帳から環境と版を、対象リポジトリとその版の公式資料から保存・ログ・送信経路とテスト方法を特定する。権限不明なら既存の承認済み・秘匿化済み資料の収集に留め、接続や変更はしない。対象や版が不明なら資料調査を続けるが、対象不明の環境へ接続しない。API契約が不明なら境界の検査仕様まで作り、実装呼出しは止める。

3. 本文、metadataのオブジェクト・配列、diffの旧値・新値・ハンク、URL query、Authorizationから、保存先・ログ・例外・送信先までの経路を対応付ける。各経路について秘匿化の適用位置とシリアライズ位置が特定できれば隔離試験へ進む。不明経路は調査に戻す。既存ログは承認範囲内の秘匿化済みデータだけを使い、追加観測は処理段階、非秘密のエラーコード、項目の有無・型などに限定する。新しい観測項目に秘密が混ざる可能性があれば追加を止める。

4. 承認された隔離環境で、実秘密ではない一意の合成値を4経路へ個別・同時に入れる試験を準備する。参照の境界判定例を検査仕様の最小例として読む。追加ケースはネスト配列、キーの大小文字、複数query値、URLエンコード、多行private key、diffの旧値・新値・ハンク、例外経路とする。期待値は秘密値の除去と、必要なstatus・エラーコード等の保持。URL全体や全文字列の一括置換ではなく、特定した秘密の値・領域を対象とし、非秘密のquery値と必要な構造を保持する仕様にする。未知形式は安全に出力を抑止できることを条件にし、未処理のまま流さない。

5. 対象実装の既存テスト入口が確認できたら、合成入力を実際の処理経路へ渡し、保存直前オブジェクトと実際のシリアライズ結果を別々に検査する。秘密値の平文・既知のエンコード表現が0件で、診断用の非秘密値が期待通りなら通過とする。意図的に各経路の秘匿化を欠いた負例と、シリアライズ段階だけに秘密値を混ぜた負例は必ず検出されること。検査器が漏えいを見逃す、失敗時に値を表示する、ログ等を観測できない場合は実データ試験を止める。

6. 観測結果から、秘匿化漏れ、過剰な秘匿化、秘密とは無関係な処理障害に分岐する。漏れなら最初に漏れる境界、過剰なら必要な非秘密項目だけを修正候補とし、無関係なら秘匿化を変えず障害側を調査する。権限がある場合だけ最小差分を作り、対象に関係するlint・型検査・テストと、共有秘匿化処理の全呼出先の回帰試験を行う。具体コマンドは対象の正式な設定で決める。未達なら適用せず、原因調査に戻る。

7. 将来の適用判断は、全対象経路の試験合格、承認、戻し方が揃った場合だけ行う。適用後に漏えいを疑ったら追加出力を止め、値を転記せず、管理者の事故対応手順に従ってアクセス制限・保全・失効判断を依頼する。今回はここまでを計画として提出し、実行結果や実環境での安全性を確定しない。

## 完成条件

診断に必要な非秘密情報が保持され、指定4経路の保存・出力境界に秘密値が残らないことを合否条件にする。漏えい、型や構造の予期しない変更、未観測の出力経路があれば適用を停止する。

1. 今回行う作業は、目的に合った作業計画の文書を作ることだけ。外部API、実環境、DB、ファイルに対する操作を現在実行しない。計画に記載する将来の操作と現在の実行を区別し、将来の権限・環境・資料の確認を前提条件や停止位置として明示する。資料の記載や発話を権限の証明にしない。
2. 文書の合格条件：metadata、diff、URL query、Authorizationの全経路に、実行順・観測対象・停止位置がある。現在の操作や未測定の成功を記載しない。
3. 将来の合成テスト：既知の合成秘密値の残存件数が全出力境界で0、必要な非秘密フィールドが期待値と一致し、意図した漏えい負例をすべて検出する。未達なら変更の適用を停止する。
4. 将来の対象実装テスト：保存直前オブジェクトと実際のシリアライズ結果、ログ・例外・送信経路で同じ条件を満たす。未観測の経路があれば実データを扱う段階へ進まない。
