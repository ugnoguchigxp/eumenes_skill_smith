## 検証（採用 / 不採用）

文書とコードを突き合わせて確認します。 変更後に `bun run verify`（Bun 1.4.4）が通り、追加した試験が変更前は失敗し変更後は通ることを確認します。既存試験が壊れた場合は不採用として戻します。

## よくなったとみなす条件

記述が実装と一致することです。

## 悪化したとみなす条件

他の記述を誤って変えることです。

## やらないこと

文書の全面改稿はしません。 本番の ContextStill への接続、語句辞書やキーワードによる意味分岐、費用上限によるゲートは行いません。推論は Grok Bot が recorded-inference の継ぎ目を通して行います。
